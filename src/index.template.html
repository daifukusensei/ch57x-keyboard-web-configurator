What do the labels and outlines mean?
  • Click a button or knob action to edit it.
  • Amber outline = warning, red = invalid.
  • R1 C1 = row 1, column 1 of the button grid, counted from the top left (R2 C3 = row 2, column 3, and so on).
  • On each knob, ↺ ccw = turn counter-clockwise, ● press = push the knob in, ↻ cw = turn clockwise.
  • A small dot in a key's corner = it has a comment.

Help and reference

Visual editor for ch57x-keyboard-tool mapping files. By daifuku.

Build a layout, then upload straight from this page, or save it with Save config and use the CLI.

Actions

Keyboard. a, enter, ctrl-c, cmd-alt-escape. Modifiers: ctrl shift alt/opt win/cmd and right-hand variants rctrl rshift ralt/ropt rwin/rcmd. A chord is one key, optionally held with modifiers (ctrl-shift-t). A sequence is up to 5 chords separated by commas, pressed one after another: win-r,c,m,d,enter opens the Run box, types cmd and presses Enter. Raw HID codes: <101>. Option prefix: {delay(100)}left,a,right. Letters are physical QWERTY keys, not characters. Run show-keys for the full key list.

Mouse. click, click(left+right), rclick, mclick, move(x,y), drag(button,x,y), wheel(n), wheelup, wheeldown, with ctrl / shift / alt only.

Media. screenbrightnessup screenbrightnessdown next previous/prev stop play mute volumeup volumedown favorites calculator screenlock webpagehome webpageback webpageforward. Media keys can't take modifiers or be mixed with normal keys.

LEDs (separate CLI command, not part of the YAML). 0x8840 / 0x8842: led <layer> <mode>… with modes off, backlight, shock, shock2, press and colors red, orange, yellow, green, cyan, blue, purple (backlight also white). 0x8890: led 1.

Boards with one row (or column) and one knob (e.g. 3×1 + 1 knob): modifiers work on the first key of a button's sequence only, as in the original tool's validate; the editor marks other uses as errors.

A key name this editor doesn't recognise gets a warning, not an error: it may be a typo, or a name the tool accepts that the editor doesn't list. ./ch57x-keyboard-tool show-keys prints every name the tool accepts. Always finish with validate.

Comments on keys

Type a note in the Comment box under the action to remember what a key does. Comments are saved at the top of the YAML, one line per key, starting with #@. The tool treats these lines as ordinary comments, so the file still validates and uploads exactly as before; comments are never sent to the keyboard. Importing a file reads them back onto their keys and turns on Show comments on keys so you can read them on the keycaps.

#@ L1 R2 C3: split; "zen" view
#@ L1 K1 ccw: zoom out
#@ L1 K1 press: reset zoom
model: ch57x-2
...

L is the layer, R and C the button row and column, and K the knob followed by ccw, press or cw, all counted from 1 in the order the file lists them (the same numbers the editor shows). The text runs to the end of the line exactly as typed, so ;, #, quotes and backslashes need no escaping. Lines that name a key the pad doesn't have are skipped, and the import message says how many. A comment written at the end of a key line (- ["a", "b"] # note) is not read.

Direct upload (WebHID)

Writes the mapping straight to the keyboard from this page (Chrome or Edge on desktop; the keyboard must be connected by USB cable). Packet formats come from ch57x-programmer. Supports ch57x-1 (1189:8840, 1189:8842), ch57x-2 (1189:8890) and ch57x-3 (514c:8850); the model: line in the YAML is filled in from the connected keyboard. 514c:8850 is shared by two different keyboards, so the protocol follows your layout: 16 buttons is the 4×4 pad, any other layout is the 12-key, 4-knob pad (protocol from ch57x-keyboard-tool-enhanced; there a click cannot carry a modifier, the wheel moves one step, and drag is unavailable). Empty actions are skipped, so whatever is on the keyboard for those keys stays unchanged.

Adds Read device info (asks the keyboard how many buttons and knobs it has; Upload then warns if your layout differs) and Preview packets (lists the bytes an upload would send, without a keyboard) to the upload bar. Remembered in this browser. Opening the page with ?debug=1 or ?debug=0 turns it on or off.

Without WebHID: the command-line tool

In Firefox or Safari, or when the browser can't reach the keyboard, save the mapping with Save config and upload it with ch57x-keyboard-tool:

./ch57x-keyboard-tool validate mapping.yaml
./ch57x-keyboard-tool upload mapping.yaml

Linux without udev rules: prefix the commands with sudo. Windows: run .\ch57x-keyboard-tool.exe the same way (needs USBDK installed). If your build reads the config from standard input: ./ch57x-keyboard-tool upload < mapping.yaml.
