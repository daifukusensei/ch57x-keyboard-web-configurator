What do the labels and outlines mean?
  • Click a button or knob action to edit it.
  • Amber outline = warning, red = invalid.
  • R1 C1 = row 1, column 1 of the button grid, counted from the top left (R2 C3 = row 2, column 3, and so on).
  • On each knob, ↺ ccw = turn counter-clockwise, ● press = push the knob in, ↻ cw = turn clockwise.
  • A small dot in a key's corner = it has a comment.

YAML: copy, download, import

Import existing YAML

The importer reads the mapping format used by the tool (model, orientation, rows, columns, knobs, layers). Per-key comments are kept: a # comment after a button row (one note per key, separated by ;) or after a knob line. Other comments, such as the header at the top of a file, are dropped when the file is re-exported.

No WebHID? Upload with the command-line tool 
./ch57x-keyboard-tool validate mapping.yaml
./ch57x-keyboard-tool upload mapping.yaml
# Linux without udev rules: prefix with sudo
# If your build reads the config from stdin instead: ./ch57x-keyboard-tool upload < mapping.yaml

If WebHID isn't available (Firefox, Safari, or your OS doesn't expose the interface), this generates a script that writes mapping.yaml, runs validate, and only then runs upload with the original tool.

Put the script next to the tool, or give the tool's full path. Linux/macOS: chmod +x upload-ch57x.sh && ./upload-ch57x.sh. Windows: powershell -ExecutionPolicy Bypass -File upload-ch57x.ps1 (needs USBDK installed).

Help and reference

Visual editor for ch57x-keyboard-tool mapping files. Build a layout, then upload straight from this page, or copy or download the YAML and use the CLI.

Comments on keys

Type a note in the Comment box under the action to remember what a key does. It is saved in the YAML as a # comment, which the tool ignores, so the file still validates and uploads exactly as before; comments are never sent to the keyboard. A button row carries one comment after the row, with one note per key in column order, separated by ;. Each knob line (ccw, press, cw) carries its own. Files written that way are read back onto the right keys when you import them, and turn on Show comments on keys so you can read them on the keycaps.

- ["ctrl-b", "ctrl-shift-v", "ctrl-k,v"]   # side bar; markdown view; markdown side-by-side
...
knobs:
  - ccw: "ctrl-minus"       # zoom out
    press: "ctrl-numpad0"   # reset zoom

A ; typed inside a button note is saved as ,, because ; separates the notes in a row. If a row has more notes than keys, the extras are joined onto the last key.

Direct upload (WebHID)

Writes the mapping straight to the keyboard from this page (Chrome or Edge on desktop; the keyboard must be connected by USB cable). Packet formats come from ch57x-programmer. Supports ch57x-1 (1189:8840, 1189:8842), ch57x-2 (1189:8890) and ch57x-3 (514c:8850); the model: line in the YAML is filled in from the connected keyboard. 514c:8850 is shared by two different keyboards, so the protocol follows your layout: 16 buttons is the 4×4 pad, any other layout is the 12-key, 4-knob pad (protocol from ch57x-keyboard-tool-enhanced; there a click cannot carry a modifier, the wheel moves one step, and drag is unavailable). Empty actions are skipped, so whatever is on the keyboard for those keys stays unchanged.

Actions

Keyboard. a, enter, ctrl-c, cmd-alt-escape. Modifiers: ctrl shift alt/opt win/cmd and right-hand variants rctrl rshift ralt/ropt rwin/rcmd. Sequences use commas: win-r,c,m,d,enter. Raw HID codes: <101>. Option prefix: {delay(100)}left,a,right. Letters are physical QWERTY keys, not characters. Run show-keys for the full key list.

Mouse. click, click(left+right), rclick, mclick, move(x,y), drag(button,x,y), wheel(n), wheelup, wheeldown, with ctrl / shift / alt only.

Media. screenbrightnessup screenbrightnessdown next previous/prev stop play mute volumeup volumedown favorites calculator screenlock webpagehome webpageback webpageforward. Media keys can't take modifiers or be mixed with normal keys.

LEDs (separate CLI command, not part of the YAML). 0x8840 / 0x8842: led <layer> <mode>… with modes off, backlight, shock, shock2, press and colors red, orange, yellow, green, cyan, blue, purple (backlight also white). 0x8890: led 1.

3×1 + 1 knob boards: modifiers work on the first key of a sequence only.

Key names outside the ones this editor knows get a warning, not an error, because the tool's own list (show-keys) is authoritative. Always finish with validate.
